# 架构决策记录（ADR）

> 本目录只放「一次性拍板、之后要被遵守」的决策。每条一个文件：`NNNN-<slug>.md`。
> 日常实现细节不进这里（→ `docs/IMPLEMENTATION-NOTES.md`）；架构总览 → `docs/ARCHITECTURE.md`。

## 索引

| 编号 | 标题 | 状态 | 日期 |
|---|---|---|---|
| — | 暂无 | — | — |

## 何时该建一条

- 两个方案都可行，选了其中一个，且以后有人会问「为什么不用另一个」。
- 决策有代价（性能、维护、安全），需要留下当时的权衡。
- 决策推翻了旧做法，需要说明旧做法为什么不再适用。

## 格式

```markdown
# NNNN. <一句话标题>

- 状态：提议 / 已采纳 / 已废弃（被 NNNN 取代）
- 日期：YYYY-MM-DD
- 决策者：<人或角色>

## 背景
## 决策
## 后果（好的与坏的）
## 替代方案及未采用原因
```

## 状态变更

废弃不删文件：改状态行，写明被哪条取代。删掉的决策等于让下一个人重犯同样的错。
